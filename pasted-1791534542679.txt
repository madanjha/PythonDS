Refined requirement

Goal: Detect mismatches between a release bulletin (PDF) and the actual files that changed in a release, in both directions.

Inputs

A file change set — one of:
two directory snapshots (--before-dir, --after-dir), or
a git repo + two refs/commits (--repo, --from-ref, --to-ref)
A release bulletin PDF (--bulletin) that lists changed files/features/fixes in prose, bullets, or a table.

Processing

Walk both trees (or run git diff) and classify every path as Added / Removed / Modified / Unchanged, using a content hash (not mtime, which is unreliable).
Extract text from the PDF and pull out every file path, module name, or feature/fix line it mentions.
Match each real file change to a bulletin mention (by path, then by filename/module fuzzy match since bulletins rarely use full paths).
Classify every item into one of four buckets:
Documented & matches — mentioned in bulletin, file actually changed.
Undocumented change — file changed, nothing in the bulletin mentions it.
Phantom entry — bulletin mentions a file/feature, but no matching file changed.
Ambiguous — bulletin mentions something but it maps to more than one changed file, or the match confidence is low.

Output: a report (console + JSON/Markdown) listing each bucket with file path, bulletin line (if any), and a one-line reason — so a reviewer can see exactly what’s missing on which side.

Explicitly out of scope for the deterministic script: judging whether a change matches the bulletin’s described intent (e.g. “fixed login timeout” vs. what the diff actually does) — that needs semantic reading of the diff, which is the Agent’s job, not the script’s.
